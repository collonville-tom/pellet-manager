# Pellet Manager - Project Context

## Project Overview
This project is a Django-based application designed to manage pellet stocks. It is containerized using Docker and Docker Compose, and includes a Jenkins CI/CD pipeline.

## Tech Stack
- **Framework:** Django 5.1+
- **Language:** Python 3.11
- **Database:** PostgreSQL 15 (Development uses SQLite as secondary/test option)
- **Containerization:** Docker & Docker Compose
- **CI/CD:** Jenkins (Pipeline)
- **Frontend:** Django Templates with CSS

## Project Structure
- `pellet_mgmt_proj/`: Main Django project configuration (settings, URLs, WSGI/ASGI).
- `pellet_mgmt_app/`: Main application logic (models, views, templates, static).
  - `templates/`: HTML templates for stock management, history, and calculations.
  - `static/`: CSS and other static assets.
- `Dockerfile`: Defines the application container.
- `docker-compose.yml`: Orchestrates the app and the PostgreSQL database.
- `Jenkinsfile`: CI/CD pipeline definition.
- `manage.py`: Django management script.
- `rebuild.sh`: Script to rebuild and restart the containers.
- `startContaineur.sh`: Script executed inside the container to run migrations and the server.

## Key Workflows
### Local Development
To start the project locally with Docker:
```bash
./rebuild.sh
```

### Database Migrations
Migrations are automatically applied on container startup via `startContaineur.sh`. Manual migrations:
```bash
docker-compose exec pellet_manager python manage.py makemigrations
docker-compose exec pellet_manager python manage.py migrate
```

### Running Tests
```bash
python manage.py test
```

## Environment Variables
The project uses `django-environ`. Key variables (stored in `.env`, ignored by git):
- `SECRET_KEY`
- `DEBUG`
- `DB_NAME`, `DB_USER`, `DB_PWD`, `DB_HOST`
